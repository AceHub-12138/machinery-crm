## 三、本次任务范围

只允许修改与本次任务直接相关的代码。

必须避免：

- 重构整个项目；
- 删除已有模块；
- 删除数据库字段；
- 清空数据库；
- 改动无关页面；
- 覆盖权限系统；
- 覆盖登录页；
- 破坏 CRM 主流程；
- 破坏已有移动端/PWA；
- 破坏天地图；
- 破坏上传文件访问逻辑。

## 四、强制安全规则

1. 生产环境绝对不能执行 `db:reset`。
2. 不能生成任何会清空数据的命令。
3. 数据库变更必须是纯新增或安全 ALTER。
4. SQL 中不能包含未经确认的 `DROP` / `TRUNCATE` / 批量 `DELETE`。
5. 合同、回款、客户、权限相关数据必须保守处理。
6. 上传目录、附件、图片不能被删除。
7. 所有价格、金额、成本、合同明细必须保留历史快照。
8. 所有库存变动必须产生库存流水。
9. 所有高风险修改必须可回滚。

## 五、当前 ERP 原则

ERP 模块应遵守：

- 新表优先使用 `erp_` 前缀。
- BOM 明细必须使用子表，不要 JSON 大字段。
- 库存扣减必须校验库存是否足够。
- 库存变动必须写入 StockMovement / 库存流水。
- 采购订单不应直接改库存，到货入库才改库存。
- 齐套检查只做计算，不直接扣库存。
- 生产领料才是真正库存扣减节点。
- WAREHOUSE 仓管角色只能访问 ERP/设置相关页面，不能获得超级管理员权限。
- ERP 不能破坏原 CRM 的销售/外贸权限隔离。
