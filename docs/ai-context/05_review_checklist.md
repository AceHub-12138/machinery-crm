# DachuanPro CRM/ERP 代码审核与上线前检查清单

## 1. 基础检查

- 确认本次修改没有推倒重建项目。
- 确认没有删除或覆盖现有 CRM 功能。
- 确认没有提交敏感信息、数据库密码、服务器密钥或生产环境账号。
- 确认没有把敏感信息写入日志。
- 确认没有提交临时调试代码、无用 console、测试账号或本地路径。

## 2. 数据与数据库检查

- 确认没有删除正式数据。
- 确认没有清空数据库。
- 确认没有未经用户确认执行破坏性数据库操作。
- 如涉及表结构变更，必须说明迁移方案、执行顺序和回滚方案。
- 如涉及正式数据字段，必须说明旧数据如何兼容。

## 3. 上传文件与附件检查

- 确认没有覆盖 uploads 上传目录。
- 确认新增上传功能不会绕过文件类型、大小和权限限制。
- 确认附件、合同、发货资料等文件路径不会泄露服务器敏感目录。

## 4. 权限检查

- 确认新增页面有角色权限控制。
- 确认新增 API 在后端校验权限，不只依赖前端隐藏。
- 确认超级管理员可以查看和管理全部数据。
- 确认区域销售只能查看自己权限范围内的数据。
- 如新增 ERP 角色，必须说明角色边界和可访问模块。

## 5. CRM 现有业务检查

- 确认客户、产品、报价、合同、回款、发货等核心流程没有被破坏。
- 确认合同与回款状态联动逻辑没有被误改。
- 确认发货与物流记录不会影响已有合同数据。
- 确认工作台、区域权限和超级管理员入口仍可正常访问。

## 6. ERP 二期模块检查

- 新增模块优先采用独立页面、独立 API、独立数据表或清晰关联表。
- 新增库存、BOM、采购、生产、成本等模块时，必须说明与现有 CRM 数据的关联方式。
- 涉及库存数量、产品配件、选配项、审批流程时，必须单独列出风险。

## 7. 测试检查

- 说明已运行哪些自动化检查，例如 lint、typecheck、build、单元测试。
- 说明未运行的测试及原因。
- 给出用户可手动操作的测试清单。
- 覆盖超级管理员和区域销售两类典型账号。
- 覆盖新增功能、受影响旧功能和失败场景。

## 8. 部署检查

- 部署前必须提醒备份项目目录。
- 部署前必须提醒备份数据库。
- 部署前确认 PM2 服务名称。
- 部署前确认 Nginx 配置。
- 部署前确认环境变量。
- 部署前确认上传目录不被覆盖。
- 每条部署命令都必须说明用途。
- 不要给用户危险的一行式命令。

## 9. 回滚检查

- 说明代码如何回滚。
- 说明数据库如何回滚。
- 说明上传文件或附件如何恢复。
- 说明 PM2、Nginx 或环境变量改动如何恢复。
- 如果无法完整回滚，必须明确告诉用户风险。

## 10. 提交检查

- 输出建议 commit message。
- 提交前说明是否已运行测试。
- 建议 commit message 示例：

```text
feat: 新增 ERP 二期 xxx 功能
fix: 修复 xxx 页面报错
refactor: 优化 xxx 逻辑
chore: 调整部署配置
```
