# 03｜ERP 二期开发上下文

## 一、当前阶段判断

从导出的资料看，DachuanPro 已经从 CRM 阶段进入 ERP 扩展阶段。历史资料里最后明确记录的是：

- ERP Phase 1 已经完成或进入部署周期；
- 版本推进到 v1.4.x；
- v1.4.2 正在处理库存增强；
- 后续方向明确指向 ERP 二期：采购、生产订单、齐套检查、成本核算。

如果现在 Codex 已经实际进入“ERP 二期开发工程”，应把本文件作为二期上下文底稿，再补充当前最新的 Codex 任务单、分支名、变更文件和报错截图。

## 二、ERP 一期基础

ERP 一期目标不是完整 ERP，而是先建立“物料/BOM/库存”的基础层。

已知一期内容：

1. 物料管理
2. 物料分类
3. BOM 表头
4. BOM 明细
5. 入库单
6. 出库单
7. 盘点单
8. 库存流水
9. 仓管角色
10. ERP 菜单和权限
11. BK5030 物料数据
12. 库存台账
13. 基础库存预警

已知数据库层面：

- ERP 表以 `erp_` 开头。
- 一期迁移脚本曾被审查为纯新增表，不应影响原有 CRM 数据。
- ERP 表包含 BOM 相关表。
- 物料分类是树形结构。
- 出入库逻辑使用事务。
- 库存流水记录变更前/后数量。

## 三、v1.4.2 库存增强

导出的记忆里明确提到 v1.4.2 重点是三个库存增强：

1. 入库/出库/盘点明细行支持物料模糊搜索。
2. 每个分类可在 UI 中配置库存预警阈值。
3. 进入库存台账时自动弹出缺货/库存预警弹窗。

相关数据库变更：

- `Material` 增加 `supplier` 字段。
- `MaterialCategory` 增加 `warningThreshold` 字段。
- 有一个 SQL 文件名类似：`erp_v142_加字段.sql`
- BK5030 物料数据脚本升级为类似：`erp_bk5030_物料数据_v2.sql`
- 新脚本中给部分物料补充供应商信息。

## 四、库存预警设计

历史方案里库存预警设计为：

- 当前库存数量 ≤ 预警线，则标记为库存预警。
- 原系统已有“安全库存”列和“仅显示预警”筛选。
- 后续改为分类级预警线：
  - 例如铸件类设置 2；
  - 电气/电子件设置 10；
  - 该分类下物料默认继承分类阈值。
- 后续可给特殊物料保留单独覆盖空间。

已知分类示例：

- 铸件类
- 机加件
- 外购机械件
- 电气/电子件
- 防护/钣金件
- 辅料/耗材
- 零件包

## 五、ERP 二期建议拆分

ERP 二期不要一次做“大而全”。建议拆成 5 个可上线小阶段。

### 二期 A：采购管理

目标：解决“缺什么、向谁买、什么时候到”。

建议模块：

- 供应商档案
- 采购申请
- 采购订单
- 采购入库联动
- 采购状态
- 采购备注
- 采购附件
- 采购价格历史

与一期关系：

- 采购订单选择物料。
- 到货后生成入库单或关联入库单。
- 供应商字段可与 v1.4.2 的 `supplier` 字段衔接。

注意：

- 采购订单不要直接改库存，必须通过入库单入库。
- 采购价格要保留历史快照。
- 不要把供应商写死在物料里，物料可以有默认供应商，但采购单必须保存当时供应商快照。

### 二期 B：生产订单 / 工单

目标：把合同或订单转成内部生产任务。

建议模块：

- 生产订单
- 关联客户合同
- 关联产品型号
- 计划开工日期
- 计划完工日期
- 当前进度
- 负责人
- 状态流转：待排产 / 生产中 / 暂停 / 完成 / 已发货

注意：

- 生产订单不等于合同。
- 合同可能包含多个设备，生产订单应支持按设备/台套拆分。
- 状态变更要有日志。
- 不要一开始做复杂排产算法，先做人工状态跟踪。

### 二期 C：BOM UI 和齐套检查

目标：判断生产一台设备需要哪些物料、库存是否够。

建议模块：

- BOM 编辑界面
- 按产品型号维护 BOM
- BOM 版本
- 按生产订单执行齐套检查
- 缺料清单
- 一键生成采购建议

注意：

- BOM 明细必须用子表，不要 JSON。
- BOM 要支持版本，否则后续产品改型会影响历史订单。
- 齐套检查不应直接扣库存，只负责计算和提示。
- 真正扣库存应在领料/出库环节。

### 二期 D：领料/退料/生产出库

目标：让库存和生产消耗关联起来。

建议模块：

- 生产领料单
- 生产退料单
- 关联生产订单
- 自动生成库存流水
- 出库前校验库存
- 支持缺料提示

注意：

- 生产领料是库存减少的正式节点。
- 不能只在生产订单状态变化时直接扣库存。
- 所有库存变动必须走库存流水。

### 二期 E：成本核算

目标：先做粗粒度成本，不要一开始做精密成本。

建议模块：

- 物料成本
- 采购价格快照
- 单台设备物料成本汇总
- 合同毛利估算
- 人工/制造费用可先手动录入
- 后续再扩展精细成本

注意：

- 成本核算必须基于快照，不能用当前物料价格倒推历史订单。
- 先做“能辅助决策”的简化成本，不要一开始做财务级精确成本。

## 六、当前最重要的拆分原则

### 1. CRM 主链路不能被 ERP 破坏

合同、客户、回款、发货是现有核心，ERP 只能向后扩展，不能影响 CRM 正常使用。

### 2. ERP 先做闭环，不先做大屏

优先级：

1. 物料数据准确；
2. 库存准确；
3. BOM 准确；
4. 采购能跟；
5. 生产订单能看；
6. 成本能粗算；
7. 最后才做看板、大屏、统计图。

### 3. 数据结构优先

ERP 不是页面堆叠，最重要的是数据库结构正确。每个模块先确认表结构、状态流转、权限、日志，再做页面。

### 4. 每个二期模块单独上线

每次只上线一个小闭环：

- 采购单
- BOM UI
- 齐套检查
- 生产订单
- 领料单
- 成本汇总

不要一次让 Codex 做完整 ERP 二期。

## 七、给新 AI / Codex 的重点提醒

1. 当前项目已经上线，不能重建。
2. 不能删除 CRM 现有表和字段。
3. ERP 新表应以 `erp_` 前缀为主。
4. 数据迁移必须纯新增或安全 ALTER。
5. 生产服务器不要跑 `prisma migrate reset`。
6. 不要直接部署 orphan branch。
7. 必须以 main 为基准嫁接。
8. 必须保留已有权限系统。
9. 必须保留登录页、安全加固、天地图、PWA。
10. 任何库存扣减必须有流水。
11. 任何价格、成本、合同金额必须保存快照。
12. 每次上线必须提供回滚方案。
