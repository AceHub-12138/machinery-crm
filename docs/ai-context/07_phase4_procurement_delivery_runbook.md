# ERP 第四期采购与交期增强：迁移及任务说明

## 边界

本次开发未连接生产服务器、未连接生产数据库、未部署、未执行 migration。上线前必须备份数据库、项目目录和上传目录，并再次确认生产路径、PM2 服务名、Nginx、`.env` 与外置 `UPLOAD_DIR`。

## 数据库文件

- 正向迁移：`prisma/migrations/20260715100000_erp_phase4_procurement_delivery/migration.sql`
- 回滚脚本：`prisma/migrations/20260715100000_erp_phase4_procurement_delivery/rollback.sql`

回滚脚本会删除本期新增业务表和字段，因此只能在确认没有需要保留的新业务数据、应用代码已先回滚且数据库备份可恢复时执行。不要执行 `prisma migrate reset` 或项目中的 `db:reset`。上线后若已产生采购需求、月度计划、调拨或交期记录，优先恢复上线前数据库备份，不要直接执行结构回滚脚本。

代码回滚应切回上线前已验证提交并重新发布原 standalone 包；附件使用外置 `UPLOAD_DIR`，代码回滚不会删除附件。若附件目录本身异常，应从上线前上传目录备份恢复，不能用发布包覆盖。回滚 SQL 为避免破坏已经存在的库存流水，不主动收缩 `StockMovementType` 的新增枚举值。

## 定时任务

设置仅服务器持有的 `ERP_CRON_SECRET`，并选定一个有效管理员用户 ID 作为系统齐套检查执行人。以下为 cron 示例，实际域名和时间需上线时确认：

```cron
*/10 * * * * curl -fsS -X POST -H "x-cron-secret: $ERP_CRON_SECRET" -H "x-system-user-id: ADMIN_USER_ID" https://YOUR_HOST/api/erp/kit-rechecks/process
0 8 * * * curl -fsS -X POST -H "x-cron-secret: $ERP_CRON_SECRET" https://YOUR_HOST/api/erp/delivery-reminders/run
```

两个任务均具备幂等约束：齐套队列按生产工单唯一，齐套快照按触发键唯一；交期通知按采购明细、日期和阈值唯一。管理员也可通过相同接口在登录状态手动执行。

## 隔离环境验收清单

执行前先在隔离测试库迁移，并记录旧采购单、库存、生产工单数量；全部场景完成后再次核对，不能误改既有数据。

1. **侧边栏滚动**：桌面端和移动端分别展开库存、采购、生产分组，滚动至最后一个菜单；预期 Logo 保持固定、菜单区域独立滚动、页面无双重异常滚动条。
2. **合同工单交期**：准备一条有明细交期、一条仅有合同表头交期的合同明细，并新建一张备货工单；预期工单快照依次取明细交期、表头交期、计划完成日期，详情只读。
3. **入库后复检**：创建缺料工单并首次齐套检查，再通过采购入库补足；运行齐套队列两次；预期旧缺料快照保留、新快照为齐套，同一触发键不重复。
4. **安全库存建议**：将物料可用量设为刚好满足工单且低于安全库存；预期仍生成补库草稿。创建已下单未入库采购后重新计算，预期建议量扣减且原有效需求被更新而非新增。
5. **备货采购**：不选合同和工单，填写物料、数量/目标库存、需要日期、用途和原因后保存；预期来源为 `STOCK_REPLENISHMENT`，审核人可追溯，交期页显示“备货”。
6. **月度计划**：建立含多个机型的计划并审核；预期 BOM/虚拟包叶子物料被合并并生成需求。先转换部分数量为工单；预期生成计划需求到工单的数量分摊关系，只对增量补采购。
7. **虚拟零件包**：整机父包用量 1，子项 2、6、3，计划数量 5；预期叶子需求 10、30、15，父包不产生库存扣减，旧 BOM 版本不被覆盖。
8. **承诺日期历史**：首次录入 7 月 20 日，再改为 7 月 25 日和 8 月 1 日；预期首次日期不变、变更次数为 2、风险按最新日期、首次兑现率按首次日期。
9. **部分到货**：采购 100，确认一张入库单 30；预期采购明细与交付批次已到 30、未到 70、状态“部分到货”。未确认批次不能直接填写实际到货，第二次入库后只核销剩余量。
10. **生产与备货合并采购**：同一物料各创建工单和备货需求，合并为一个采购明细；预期来源展开显示两条数量分摊。分批入库后分别核销来源，取消/反关联入库时反向恢复，不能重复计算。

最后在 Linux standalone 干净目录验证 Prisma 6.8.2、应用启动和 `/login` 返回 200/302/307。附件目录必须继续使用外置 `UPLOAD_DIR`，部署包不得覆盖正式上传目录。
