- 原 seed 创建超管 1、销售 3、外贸 1、客户 8、合同 3。密码随机，只在仓库外私有临时文件及进程环境；worktree 内未创建 .env。测试上传目录位于仓库外。
- 开发阶段先用 LEAD_TYC_MOCK=1 / LEAD_HUNTER_FAKE_SEARCH=1。为核对非模拟结果分类、计费标志、额度拦截和引擎不同原文场景，随后使用仓库外测试 preload：实际供应商 URL 在 fetch 前改投 127.0.0.1 模拟服务，剥离供应商 Authorization；Socket 层另拒绝所有外网连接。配置中的 key/token 只是本地合成占位值，未读取真实凭据、未发出真实供应商请求。
- controlled 阶段的 charged=true 代表应用逻辑预留，不是真实费用；合成结果 isMock=false 只为验证生产分类分支，不代表真实供应商认证。缓存、额度、分配和并发通过实际 API 与真实 MySQL 验证。
- 引擎阶段也通过真实任务创建／详情 API；搜索和评分返回作者预设的合成原文，18 个场景均落真实候选表。入池场景先写入合成历史候选，再调用实际入池接口。测试账号区域改动只在一次性库中，单独记录。
- 浏览器为实际 Chrome，账号为 seed 合成账号；接口结果与页面结果分开记录。验收基址 `http://127.0.0.1:58575`，清理后不再提供服务。

原始 HTTP：[v2-retest-http.jsonl](evidence/v2-retest-http.jsonl)。逐项断言：[v2-retest-results.jsonl](evidence/v2-retest-results.jsonl)。每组后对 leads、候选、核验记录、额度表和操作日志 SELECT，保存在 evidence/v2-db-*.json。

## 临时验收工具纠正（不隐去失败记录）

本轮未确认新的业务缺陷。临时工具曾出现下列误判／模拟器故障，发生后先暂停、只读核对，修正测试工具后仅继续未完成项；没有删除数据、降低产品断言或修改本轮范围外源码：

1. “D1简称”恰为 4 字，符合既有允许主体匹配的规则，错误预期为丢电话；更正后用文档指定的两字“恒精”验收。
2. R7 长主体换后缀应保留，临时预期写反；据已有 HTTP／DB 输出重新评估为通过，没有改写原始证据。
3. 姊妹公司测试沿用了前一个正例公司名，先触发 ALREADY_IN_POOL，未走电话重验；保留该幂等记录，改用另一合成企业覆盖目标规则。
4. 引擎模拟器按 goal 标记把评分请求误回成关键词 JSON，实际任务正确记录 parseFailed=1；修正仓库外模拟器按 system 角色分发。
5. 模拟器正则仅识别小写场景 key，R7 大写触发模拟器 AttributeError／断开连接，实际任务按 failed 收尾；修正模拟器后只执行剩余两项，失败任务仍保留。

详见 [工具纠正记录](evidence/v2-harness-correction.txt)。JSONL 中的原始 false 条目对应上述无效测试，后续有效用例以不同名称记录；不能按最后一句 PASS 隐去此前记录，也不能把工具错误归为产品缺陷。
